# Candidate Model Licensing: YOLO11n, YOLOX-Tiny, and RF-DETR Small

Last reviewed: 7 September 2026

This report compares the three object detectors evaluated by this project. It
focuses on whether each candidate can be used in a proprietary commercial system
without purchasing a separate model licence or releasing the system's source
code.

> This is a technical licensing assessment, not legal advice. The licence of the
> selected code, checkpoint, dataset, dependencies, and deployment components
> should be reviewed together before release.

## Decision summary

For a closed-source product, **YOLOX-Tiny and RF-DETR Small are the preferred
licensing candidates**. Both are distributed under Apache-2.0, a permissive
licence that allows commercial and private use subject to notice and attribution
conditions.

**YOLO11n remains useful as a technical benchmark**, but the default Ultralytics
licence is AGPL-3.0. Ultralytics states that projects using its code or models
must either comply with its AGPL-3.0 requirements or obtain a paid Enterprise
License. It is therefore not the default choice for a closed-source product.

| Candidate | Project scope | Upstream licence | Closed-source commercial fit |
| --- | --- | --- | --- |
| YOLO11n | Ultralytics package, `yolo11n.pt`, and fine-tuned weights | AGPL-3.0 by default; paid Enterprise License available | Conditional: use only with an Enterprise License or an AGPL-compliant release |
| YOLOX-Tiny | Official YOLOX code and COCO-pretrained checkpoint | Apache-2.0 | Good, subject to Apache notices and third-party checks |
| RF-DETR Small | `rfdetr[train]==1.10.0`, Small checkpoint, and fine-tuned weights | Apache-2.0 for the open-source package and Apache-designated models | Good; remain on an Apache-designated model |

## YOLO11n

The official YOLO11 documentation identifies YOLO11 models as available under
AGPL-3.0 and the Ultralytics Enterprise License. The public Ultralytics source
repository is also licensed under AGPL-3.0.

AGPL-3.0 permits commercial use, but it is a strong network-copyleft licence.
Ultralytics' own licensing guidance takes a broad position: if Ultralytics code,
architectures, training pipelines, or trained or fine-tuned models are used, the
entire project must be released under AGPL-3.0 unless an Enterprise License is
obtained. Ultralytics explicitly includes private applications, internal R&D,
SaaS, embedded deployments, and custom-trained models in this guidance.

The Enterprise License permits proprietary and commercial use without the
AGPL-3.0 open-source obligations. Pricing is not published as a standard fee;
Ultralytics provides a tailored quote. Its public platform subscriptions and
software licences are separate, so a Free or Pro platform subscription does not
replace the Enterprise License.

**Project position:** retain YOLO11n as a research and performance baseline. Do
not ship its package, original checkpoint, fine-tuned weights, converted model,
or closely integrated inference code in a proprietary product without either:

1. a documented AGPL-3.0 compliance plan reviewed for the intended system; or
2. an Ultralytics Enterprise License covering the project and deployment.

## YOLOX-Tiny

The official Megvii YOLOX repository, including the YOLOX-Tiny implementation,
is released under Apache-2.0. The repository also provides the official
COCO-pretrained YOLOX-Tiny checkpoint used as the starting point in this project.

Apache-2.0 allows use, modification, distribution, sublicensing, and commercial
use. It does not require the larger proprietary application, modifications, or
fine-tuned model to be released as open source. It also supplies an express
patent licence from contributors, subject to its terms.

If YOLOX or a derivative is distributed, the principal obligations are to:

- include a copy of Apache-2.0;
- retain applicable copyright, patent, trademark, and attribution notices;
- retain relevant `NOTICE` contents if a `NOTICE` file applies; and
- identify files that have been modified.

Apache-2.0 does not grant rights to project trademarks and provides no warranty.

**Project position:** YOLOX-Tiny is suitable for proprietary commercial use,
provided the released product includes the required notices. Before release,
record the exact source revision and checkpoint checksum and confirm that the
downloaded checkpoint has no additional terms attached to its release asset.

## RF-DETR Small

RF-DETR now has a **component-specific licensing split**. The upstream project
states that the open-source `rfdetr` package and its Apache-designated model
weights are Apache-2.0. Its current detection model table identifies Nano,
Small, Medium, and Large as Apache-2.0 models.

This repository evaluates `RFDETRSmall` with `rfdetr[train]==1.10.0`. RF-DETR
Small is therefore within the Apache-designated group and has the same
commercially permissive position and distribution obligations described for
YOLOX.

The distinction matters because the RF-DETR-XL and RF-DETR-2XL detection models,
and the `rfdetr_plus` extension they require, are licensed under the Platform
Model License 1.0 (PML-1.0), not Apache-2.0. PML-1.0 requires a separate platform
agreement and continued account good standing. It also contains usage-tracking,
reporting, and redistribution conditions.

**Project position:** RF-DETR Small is suitable for proprietary commercial use
under Apache-2.0. Do not replace it with an XL or 2XL detection model or add
`rfdetr[plus]` without a new licensing review and an applicable Roboflow platform
agreement. Recheck the model-specific licence whenever upgrading `rfdetr`, since
the package licence alone is not sufficient to classify every optional model.

## Comparison of practical obligations

| Question | YOLO11n default | YOLOX-Tiny | RF-DETR Small |
| --- | --- | --- | --- |
| Commercial use possible? | Yes, with AGPL compliance | Yes | Yes |
| Closed-source deployment without a separate paid model licence? | Not under Ultralytics' stated position | Yes | Yes |
| Must the proprietary application be open-sourced? | Ultralytics says yes unless Enterprise-licensed | No | No |
| Preserve licence and attribution notices when distributing? | Yes | Yes | Yes |
| Express contributor patent grant? | Yes, subject to AGPL-3.0 | Yes, subject to Apache-2.0 | Yes, subject to Apache-2.0 |
| Model-specific caveat | Enterprise terms are required for proprietary use | Verify each checkpoint release | Avoid PML-licensed XL/2XL detection models |

## Recommendation and release controls

Use **RF-DETR Small or YOLOX-Tiny** as the candidate for a proprietary product.
Choose between them on measured accuracy, latency, hardware support, and
maintenance needs rather than licence permissiveness; both use Apache-2.0 in the
scope evaluated here.

Keep YOLO11n as a benchmark unless the project is intentionally released in an
AGPL-compatible form or an Enterprise License is purchased.

For any production candidate:

- pin the source version and store the exact upstream licence text;
- record pretrained and fine-tuned checkpoint provenance and checksums;
- include required licence and `NOTICE` material in the distribution;
- review the licences of datasets, annotation exports, dependencies, export
  runtimes, and deployment SDKs separately; and
- repeat the review when changing package versions, model variants, checkpoint
  sources, or hosting arrangements.
